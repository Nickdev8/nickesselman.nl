## Prioritized findings

1. **Preloaded icon font dominates transfer.** `index.html` preloads the full Devicon WOFF at high priority on every route. First Lighthouse run: 1,500,784 font bytes out of 1,733,468 total bytes (87%). Replace with the icons actually used, preferably local SVGs or a subset. Remove the global font preload once the replacement is ready. Re-measure under the same conditions; byte reduction is clear, exact LCP savings remain unverified.
2. **The mobile LCP portrait is lazy-loaded.** Lighthouse identifies `section#about > img.portrait`; `src/App.jsx` renders `<Portrait />` without its existing priority option. Use the priority option for this visible homepage image and correct its `sizes` to match the rendered layout. Lighthouse estimated 21 KiB image savings. The trace-derived breakdown in run 1 attributes about 1.17 s of the observed navigation to resource discovery delay; this differs from the simulated 9.92 s headline LCP.
3. **Development dependency vulnerabilities.** `npm audit`: 9 affected packages, 6 high, 1 moderate, 2 low. Packages: Vite, PostCSS, picomatch, nanoid, browserslist, source-map-js, baseline-browser-mapping, Babel core, esbuild. All report fixes available. `npm audit --omit=dev`: zero vulnerabilities. Update compatible versions and run the complete build; these findings do not establish an exploitable production static site.
4. **External stylesheet lacks SRI.** The pinned jsDelivr Devicon stylesheet in `index.html` has no integrity attribute. Self-hosting the reduced icon assets addresses both this supply-chain exposure and the largest transfer problem.
5. **Security hardening remains.** Live HTML includes CSP, nosniff, Referrer-Policy, frame denial and Permissions-Policy. HSTS is absent. Roll out host-scoped HSTS after HTTPS verification; do not add includeSubDomains/preload without checking subdomains. CSP uses script host allowlists; consider hashes/nonces and report-only Trusted Types after compatibility testing. These are defense-in-depth gaps, not demonstrated XSS vulnerabilities.
6. **Secondary loading opportunities.** Lighthouse estimates 61 KiB unused JavaScript and 520 ms render-blocking savings in run 1, including the external icon stylesheet. Address the font and portrait first, then reassess route splitting. Source configuration caches unhashed images and media for a year; use versioned URLs or shorter cache lifetimes when replacing assets to avoid stale clients.

## Passing checks and limits

HTTPS and HTTP/2 observed; deployed CSP includes base-uri, form-action and frame-ancestors. No browser console errors observed on the homepage. Lighthouse Best Practices passes all scored checks, but its informative security warnings remain despite the 100 score. Source has HTML5 doctype, charset first in head and viewport declaration. Initial JS transfer is about 120 KB; CSS about 32 KB. CLS and main-thread blocking are low relative to the loading problem.

This was a homepage audit, not exhaustive route, interaction or penetration testing. Field data could not be retrieved, so real-user Core Web Vitals status is unknown. No before/after improvements are claimed.

## Local implementation and verification

Implemented locally on 2026-10-24; no deployment or push.

- Removed the global Devicon font/CSS dependency and its CSP origin allowance. The portrait interaction requests 78 local SVGs only when activated (164,610 bytes combined), with upstream MIT license included. The old `npx` icon class had no upstream SVG and was omitted. Physics boxes and visual icon size are preserved.
- Homepage portrait now loads eagerly at high priority, with layout-specific responsive sizes. Other portrait sizes match the about-page layout.
- Compatible lockfile updates include Vite 7.3.7; full and production-only npm audits now report zero vulnerabilities.
- nginx now caches unhashed media/scripts/styles for one day and fingerprinted JS/CSS for one year. Project-media noindex headers remain intact.
- Prepared host-only five-minute HSTS and report-only Trusted Types headers. No reporting endpoint was added; browser console diagnostics are available during testing. These headers are configured locally, not active in production.
